## Three method findings

**1. The `.ipynb` hash is a poor change detector.** All seven re-runs showed a changed notebook
hash, because re-running rewrites output cells and execution counts. Only the extracted `main.py`
hash tells you whether the agent moved - and that is what exposed the four-way collision. Yesterday's
rule said "diff the .ipynb sha256"; correct it to **diff the extracted agent's sha256**.

**2. The AST "last FunctionDef" shortcut is NOT Kaggle's rule and disagrees in practice.** Kaggle
takes the last *callable in the module namespace*. On three of nine builds today the two differ:
`haodou3` is `submission_v67` not `_dsm_crop_prices`; `shepherds2` is `hs4_ig_agent` not
`kaggle_submission_agent`; `hybrid2965c` is `v7_hr_agent` not `kaggle_submission_agent`. Load the
module and read `vars(m)` order, as `mirror_all.py` does.

**3. `iceandfire` is inert under Kaggle's own rule.** Its last callable is
`install_water_repair_local_patch`, a patch installer. It banks exactly 3,000 - the starting cash -
in every game and never acts. That is not a weak agent, it is a broken submission, and we cannot
evaluate the agent the author intended without guessing which callable he meant.

Also: `poprobust2` and `godsmode` have different file hashes but produce **identical** banks on
identical seeds (148,599 on seed 1). Functionally one agent. Both play correctly and lose every
game by about 1.4K.
