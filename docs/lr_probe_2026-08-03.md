# The learning-rate probe: `3e-5` versus `2e-4`

**Date:** 2026-08-03.
**Status:** decisive at the 58-update matched window; arm 2 still running to 120 (ETA ~14:03).

## Why it was run

Fable's item 3 (`docs/fable_review_day0_launch_2026-08-03.md`) found that my premise for raising the
learning rate was wrong.
`3e-5` is not a resume-only value — it is the only value this project has ever run on this
architecture, fresh or resumed, and `HANDOFF.md:694` records it as adopting Ender's number.
The code default is `3e-4` (`train_jax_rl.py:1239`), and `optax.adam(args.lr)` carries **no schedule**
(`:1673`) — no warmup, no decay — so whatever is chosen applies at full strength on the last update
exactly as on the first.
A jump to `2e-4` held flat for 20,000 updates is an intervention, not a tweak, and there was no
ablation on record in either direction.

The instrument nominated by both Fable and `CLAUDE.md` is `clip_frac` as early warning.

## Setup

Both arms are identical except for `--lr`, and both carry today's two fixes — `--gamma-per-day 1.0`
(the `seat_loss`/discount inconsistency) and `--kl-anneal 4000` (the shape prior's release valve).
So this probes the learning rate against the *corrected* config, not the old one.

```
--batch 256 --horizon 32 --updates 120 --minibatch-size 512 --epochs 2 --n-phases 256
--opponent-frac 0.45 --idle-frac 0.10 --trade-frac 0.00 --farm-frac 0.25 --ranch-frac 0.20
--pool-size 16 --early-limit 0 --seat-coef 1.0 --ent-coef 0.01 --pool-every 25
--hand-prior 0.15 --spend-prior 0.05 --gamma-per-day 1.0 --kl-anneal 4000
```

Run sequentially, not concurrently — rollout needs ~2.6 GiB and the training epochs another ~2.7 GiB,
and running both at once OOM'd the 16 GiB card at `XLA_PYTHON_CLIENT_MEM_FRACTION=0.35`.

- arm 1: `probe-lr3e5-20260803-122914`, 120/120 complete, 36 minutes.
- arm 2: `probe-lr2e4-20260803-131242`, running.

## Result

`2e-4` loses on every instrument, and loses badly.

|---|---|---|
| `clip_frac` mean | **0.024** | 0.174 |
| `clip_frac` max | **0.160** | 0.344 |
| updates above the from-scratch band (0.012–0.083, `HANDOFF.md:552`) | **3/58 (5%)** | 51/58 (88%) |

| `approx_kl` max | **0.027** | 0.045 |

## What the numbers say

**`clip_frac` answered it inside four updates.**
Arm 2 read 0.172 / 0.152 on its first two logged updates against arm 1's 0.098 / 0.047, and never
came back — 88% of its updates sit above the top of the band a from-scratch run is supposed to
occupy.
`CLAUDE.md` nominates this as the early-warning instrument precisely so a bad LR costs four updates
instead of twenty thousand, and here it did exactly that.

**The decisive number is `ev_signal`, not `clip_frac`.**
`ev_signal` is explained variance restricted to terminal rows — how well the critic predicts the
actual game outcome, which after today's `seat_loss` fix is the one thing the whole run turns on.
At the matched update 57 it reads **0.482 at `3e-5` and 0.080 at `2e-4`**: a factor of six.
`2e-4` does not merely add noise on top of equivalent learning.
It prevents the critic from learning at all.

That matters more than it looks, because of the credit-assignment arithmetic in
`docs/opus_review_2026-08-03.md`: with `--horizon 32` and `--gae-lambda 0.95`, a direct path from the
terminal reward back to an action exists only for the last ~32 turns of a 719-turn game.
For the other 96%, the critic is the *only* carrier of credit.
An LR that flattens the critic does not slow the run down — it removes the learning signal from
almost the entire episode.

**Entropy is a red herring here.**
Arm 2 falls faster (7.39 vs 8.30), which in isolation could be read as "learning faster".
Read against `ev_signal` it is the opposite: the policy is committing to a shape while the critic
that is supposed to be scoring that shape is still at 0.08.
That is the collapse mode, not progress.

**`grad_norm` is the one instrument that shows nothing** — 0.994 vs 1.050, essentially identical.
Worth recording because it is the number one would reach for to detect an LR that is too high, and it
would have missed this completely.

## Conclusion

**Keep `3e-5`.**
The funded run should not switch.

The finding is stronger than "no evidence to move": there is now a direct ablation showing `2e-4`
costs a 6× reduction in the exact metric this project has spent the day trying to raise.
`3e-4`, the code default, is untested and is 10× the value we are keeping — it should not be reached
for casually on the strength of being a library default.

## What this does *not* settle

The probe fixes the learning rate.
It says nothing about the open question from `docs/opus_review_2026-08-03.md` — whether the day-0
frame has a usable policy gradient at all, given zero wins against `farm`/`ranch`/`idle`.
Arm 1's own numbers are mildly encouraging on that (`ev_signal` reaches 0.54 by update 119, so
outcomes *are* becoming predictable from state), but 120 updates is 1.0M turns, roughly 3% of an
Atari run, and nothing about win rate can be read at that scale.
