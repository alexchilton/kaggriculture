Four bugs found, all of the same family: **something failed and still reported a number.**

| bug | how it hid | measured |
|---|---|---|

## The tape gate

`tests/test_each_day_matches_the_tape.py` was **295 failed / 499 passed**, and every failure was
structural.

The agent arms three recordings in one season and the gate compared all 30 days to the first:

    kawashigi/92498144.json              d0-d4
    kawashigi/92466371.json              melon latch, d3
    downloads_2026-08-13/91907974.json   q4 latch, DECIDE_BY_DAY = 5

d0-d4 were exact; the first failing cell was `BUY_SEED-5`, then melon/strawberry split at d7.
It was asking an agent whose whole job is to leave a recording why it had left it.

The tape side is now played once per recording the agent actually armed, against the same
opponent, and each day is compared to the one that governed it.
Which recording that is comes from the agent, not from a second copy of the latch logic: `replayed`
asks `step not in opening` once a turn on exactly the opening it chose, so a dict subclass over
`_replay_opening` records it with no change to the agent.

    before   295 failed, 499 passed, 84 xfailed, 37 xpassed
    after    900 passed

**It still discriminates.** Dropping d20 from `REPLAY_OPENING_DAYS` turns d20 red on 9 rows and the
damage carries forward exactly as the file's header promises: 49 failed, d20 through d29, nothing
before d20 touched.

The four contested rows gate now too.
`money`, `owned`, `SELL` and `BUY_PRODUCT` were `xfail(strict=False)` because two different seats
drained one shared market book; a replay against its own recording posts the same orders in the same
slots, so the book drains identically and all 120 cells xpassed the moment the fixture was
repointed.

## The land bill

`_land_bill` priced `LAND_PRICES[:row["land"]]`.
`row["land"]` is how many parcels the DAY buys, almost always 1, so it billed $1,000 on every land
day while `_do_buy_land` charges `LAND_ORDER[owned]`:

    d4    1st parcel, costs 1,000   billed 1,000    correct by coincidence
    d6    2nd parcel, costs 2,000   billed 1,000    under by 1,000
    d10   3rd parcel, costs 4,000   billed 1,000    under by 3,000

The error grows exactly as the parcels get expensive, so the funding rule was least reliable on the
days the farm is most stretched.

Not dead code: `_days_bill` is called **1,382 times** and `_land_bill` **2,045 times** in one full
season, measured by spy rather than by grep.

**Measured inert.** With the fix and without it the same season banks $96,198 and emits
SELL 1985 / BUY_LAND 3 / HARVEST 388 / PLANT 203 / WATER 936 — identical, because with
`REPLAY_OPENING_DAYS` covering all 30 days every emitted action comes from the tape.
Kept anyway: the arithmetic is right, it is pinned by a test, and it is the number any planned day
would read.

## The suite is deterministic, and that is what makes the red set worth anything

Two full runs at commit `2dd14b0`, same command, same machine:

    run E   189 failed, 2513 passed, 208 skipped, 47 xfailed, 10 xpassed   325.80s
    run F   189 failed, 2513 passed, 208 skipped, 47 xfailed, 10 xpassed   340.31s

    failures E 189   failures F 189   in both 189   moved 0

Four attempts were needed and the first three were wrong in the same way.

    1  named 7 leaked constants          20 tests still moved
    2  found cover.PRECOMPUTED_ROUTES    20 still moved
    3  guard discovers all globals       18 still moved
    4  bisect: 8 files in one process    16 failures twice, = the sum of running each alone
                                         -> deterministic in-process; xdist was the variable

Steps 1-3 guessed at which state leaked.
Step 4 was the first measurement of whether state leaked *at all* between those files, and it did
not — the guard had already closed it, and `--dist load` handing tests to workers in a different
order each run was doing the rest.
The fix is `--dist loadfile` in `pyproject.toml` plus the conftest guard widened to the private
caches.

A stable red set means 189 is a backlog that can be worked through, and any new red is a regression.

## The money gate: same defect as the tape gate, and a weaker gate once fixed

`tests/test_the_money_lands_on_his_turn.py` compared our fill hours to kawashigi/92498144 for all 30
days.
Measured with the same `_WhichTape` spy, seed 11:

     day  tape the agent replayed                               failing ops
       0  data/seed_scripts/kawashigi/92498144.json             -
       ...
       4  data/seed_scripts/kawashigi/92498144.json             -
       5  data/seed_scripts/downloads_2026-08-13/91907974.json  BUY_SEED
       ...
      29  data/seed_scripts/downloads_2026-08-13/91907974.json  HIRE

The q4 latch arms on d5 and the agent changes recording.
Every day the two tapes agree, the gate passes on every op; every failing day is a day it compares
two different games.
Fixed in `0879fa8`: **30 failed, 91 passed** became **121 passed, 30 xpassed**.

**Record the caveat with the win.**
The 30 xPASSed cells are the contested SELL cells, marked xfail because a fill turn is "partly the
opponent's doing".
They pass because we replay that recording's actions against that same opponent, so it is the same
game.
With `REPLAY_OPENING_DAYS = tuple(range(30))` the agent makes no purchase decisions of its own, so
what is left is a replay-fidelity check, not a cadence gate.
A green run there is not evidence our timing is good.
The same caveat applies to the per-day gate's 295 -> 900.

## A hypothesis that the measurement killed

`test_every_seat_the_day_owns_is_given_work.py` fails 22 times, 9 of them saying "day N never called
`crew.cover` — the planner did not run".
The obvious read is that `REPLAY_OPENING_DAYS = tuple(range(30))` means the planner never executes,
so these are red by construction like the tape gate was.

Probed by forcing `REPLAY_OPENING_DAYS = ()` for one pytest session
(`data/logs/noreplay_probe_2026-08-22.log`):

    22 failed   replay on  (shipped config)
    23 failed   replay off (planner runs)

**Refuted.**
Slightly worse, not better.
Those 22 are real — genuine planner defects or stale expectations, but not an artifact of the
replay.
Recorded here so the next session does not re-derive the same wrong tidy story.
